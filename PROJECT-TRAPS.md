# Project traps

- **Keep the data handlers when the panel connection reconnects, and never stop the reconnect.** Upstream v0.1.5 called `createConnection(() => {}, () => {}, () => {})` in `SocketManager.handleReconnect` and stopped after 5 attempts. The bridge was connected again but processed no frame until a restart, while a process health check stayed green. `tests/SocketManager.test.mjs` and `tests/Replay.integration.test.mjs` cover this. Judge health by panel data flow (`src/utils/Heartbeat.mjs`), not by the process.
- **Pass the configured log level to `initLogger`.** Upstream `src/index.mjs` called `initLogger()` without it, so `LOGLEVEL` had no effect and production always logged at info. Frame lines (`Processing hex string`) appear only at debug.
- **Do not assume complex 400H addresses on another panel.** A hiplex 8400H reports area 1 at `0x0500`, not `0x0530`, and its detector positions follow the Meldebereich number. Positions that come from an example configuration read as constant inactive bits and give a permanent `disarmed`. Use `AREA_STATE_ADDRESS`, positions with a `role`, and discovery mode. See `HIPLEX-8400H.md`.
- **Never put a real installation's detector list into this public repository.** It describes the alarm system of a house. Keep it in the private deployment repository; this repository holds generic examples only.
- **Local setup:** the tests import `src/config`, which is ignored by git. Copy `src/config-example` to `src/config` first (CI does `mv`). `yarn.lock` is a Yarn 1 lockfile; Yarn Berry rejects it with `--frozen-lockfile`, so use Yarn 1.22. `.husky/pre-commit` contains a machine-specific Yarn path.
- **Jest runs with fake timers globally.** `setImmediate` and `setTimeout` do not fire in a test unless the file calls `jest.useRealTimers()`. Wait for promise callbacks with repeated `await Promise.resolve()`.
- **Create a release tag inside the publishing workflow, not in a second workflow.** A tag that the workflow pushes with `GITHUB_TOKEN` does not start another workflow run. The monthly rebuild in `.github/workflows/docker-publish.yml` therefore builds, pushes the version tag and creates the release in one run. GitHub also disables scheduled workflows after 60 days without repository activity; Renovate commits count as activity.
- **Declare `@eslint/js` as a dev dependency.** `eslint.config.mjs` imports it. ESLint 10 no longer installs it, so `yarn lint` failed with `ERR_MODULE_NOT_FOUND` after the update. `yarn lint` is not part of the CI; run it before you merge an ESLint update.
- **Pass `quiet: true` to `dotenv.config`.** dotenv 17 and later print a line at every call. The container starts with the `.env` copy of the example file, so every start logged a misleading "injected env" line.
- **Install Yarn in the Dockerfile.** Node.js images from version 25 (including `node:26-alpine`) contain neither Yarn nor Corepack. `yarn: not found` broke the image build on `main` after the Node 26 update (2026-11-11); no image was published. The CI job `docker-build` now builds the image on every pull request. The build in `docker-publish.yml` runs only after a merge.
